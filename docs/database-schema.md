# Rankr — Database Schema (inferred from source)

## SSR Audit Note

`lib/supabase.ts` uses a spread-conditional to gate AsyncStorage:

```ts
...(Platform.OS !== 'web' && { storage: AsyncStorage }),
```

This is correct. On web, `AsyncStorage` is not included as the session storage backend, so Supabase falls back to its default in-memory store (or `localStorage` if available in the browser environment). No `window`, `localStorage`, or other browser-only APIs are referenced at module top-level in any `lib/` file. The SSR fix is sound.

## Tables

### `auth.users` (Supabase-managed)

Managed by Supabase Auth. The app reads `user.id` and `user.email` via `supabase.auth.getUser()`. Never queried directly via `.from()`.

| Column   | Type   | Notes                          |
|----------|--------|--------------------------------|
| id       | uuid   | PK, used as FK in other tables |
| email    | text   | Used as display fallback name  |

### `profiles`

Stores public user metadata. Created/upserted from `profile-settings.tsx`. The `id` column mirrors `auth.users.id`.

| Column       | Type    | Nullable | Notes                                   |
|--------------|---------|----------|-----------------------------------------|
| id           | uuid    | NOT NULL | PK, FK → `auth.users.id`               |
| display_name | text    | YES      | User's chosen display name              |
| username     | text    | YES      | @-handle shown in UI                    |
| bio          | text    | YES      | Free-text profile description           |
| avatar_url   | text    | YES      | Public URL from Supabase Storage bucket `avatars` |

Accessed via:
- `select('*').eq('id', user?.id).single()` — load profile
- `upsert({ id, display_name, username, bio, avatar_url })` — save profile

### `lists`

Top-level container for a ranked collection.

| Column      | Type      | Nullable | Notes                                              |
|-------------|-----------|----------|----------------------------------------------------|
| id          | uuid      | NOT NULL | PK (auto-generated by Supabase)                   |
| user_id     | uuid      | YES      | FK → `auth.users.id` (set on insert, never filtered in queries — see GAPS) |
| title       | text      | NOT NULL | Display name of the list                          |
| description | text      | YES      | Optional description                              |
| category    | text      | NOT NULL | Enum-like: `'movies'` \| `'music'` \| `'games'`  |
| created_at  | timestamptz | YES    | Auto-set by Supabase (used for ordering)          |

Accessed via:
- `select('*').order('created_at', { ascending: false })` — list all
- `select('id, title, category').eq('category', item.category)` — filter by category for search flows
- `select('id, title, category')` — load all for profile stats
- `select('title').eq('id', item.list_id).single()` — N+1 join (to fix)
- `insert({ title, description, category, user_id })` — create
- `delete().eq('id', id)` — delete list

### `list_items`

Individual items inside a list. Each item belongs to exactly one list.

| Column      | Type      | Nullable | Notes                                                                 |
|-------------|-----------|----------|-----------------------------------------------------------------------|
| id          | uuid      | NOT NULL | PK (auto-generated)                                                   |
| list_id     | uuid      | NOT NULL | FK → `lists.id`                                                       |
| title       | text      | NOT NULL | Display title (movie name, game name, track name)                    |
| subtitle    | text      | YES      | Secondary label (release year, artist name)                          |
| image_url   | text      | YES      | Remote URL from TMDB / RAWG / iTunes                                 |
| external_id | text      | YES      | ID from the external API (TMDB movie ID, RAWG game ID, iTunes trackId) |
| category    | text      | YES      | Mirrors parent list category: `'movies'` \| `'music'` \| `'games'`  |
| rank        | float8    | YES      | Numeric score in range ~1–10.5; null = unranked; managed by binary comparison algorithm |
| sentiment   | text      | YES      | `'liked'` \| `'didnt_care'` \| `'didnt_like'` \| null               |
| notes       | text      | YES      | User's free-text notes about this item                               |
| photo_urls  | jsonb     | YES      | JSON array of image URIs — **currently stored as `file://` local paths, which break on restart** |
| bookmarked  | boolean   | YES      | `true` = "save for later" (not yet ranked); `false` = ranked item    |
| created_at  | timestamptz | YES    | Auto-set by Supabase                                                  |

Accessed via:
- `select('id, title, subtitle, image_url, rank, sentiment, created_at, list_id').order('created_at', { ascending: false }).limit(20)` — home screen
- `select('*').eq('list_id', id).order('rank', { ascending: false, nullsFirst: false })` — list detail
- `select('id').eq('list_id', ...).eq('external_id', ...).single()` — duplicate check
- `select('id, title, image_url, rank, sentiment').eq('list_id', ...).not('rank', 'is', null).order('rank', { ascending: false })` — binary comparison pool
- `select('id, sentiment').eq('list_id', ...).is('rank', null).eq('bookmarked', false)` — initial batch ranking
- `select('image_url').eq('list_id', ...).order('rank', { ascending: false, nullsFirst: false }).limit(1).single()` — top item image
- `select('*', { count: 'exact', head: true }).eq('list_id', ...)` — count items per list
- `select('rank, sentiment, list_id')` — profile stats
- `insert({ list_id, title, subtitle, image_url, external_id, category, sentiment, notes, photo_urls, rank, bookmarked })` — add item
- `update({ rank }).eq('id', ...)` — update rank
- `update({ notes, photo_urls, sentiment }).eq('id', ...)` — edit item details
- `update({ bookmarked: false }).eq('id', ...)` — move to rankings
- `delete().eq('id', ...)` — remove item

## Foreign Key Relationships

```
auth.users.id  ←──  profiles.id          (1:1, user owns one profile)
auth.users.id  ←──  lists.user_id        (1:many, user owns many lists)
lists.id       ←──  list_items.list_id   (1:many, list has many items)
```

Note: `list_items` has no direct `user_id` column. User ownership is inferred through `lists.user_id`.

## Notes on Special Columns

### `rank` (float8)
- Range: nominally 1–10, but can exceed 10 (e.g. `rankedPool[0].rank + 0.5` when new item is ranked first) or go below 1 (e.g. `rankedPool[last].rank - 0.5` when ranked last)
- Null = item not yet ranked
- Driven by a binary-comparison algorithm within sentiment bands
- Drag-reorder in the list detail recalculates ranks as evenly spaced floats from 10 down to ~1

### `sentiment` (text enum)
Valid values observed in code: `'liked'`, `'didnt_care'`, `'didnt_like'`, or `null` (bookmarked items have no sentiment).
The corresponding rank bands are:
- `liked` → 7.0–10.0
- `didnt_care` → 4.0–6.99
- `didnt_like` → 1.0–3.99

### `photo_urls` (jsonb / text[])
Stored as a JSON array of URI strings. Currently the app pushes raw `file://` URIs from `expo-image-picker` directly into this column. These URIs are device-local and become invalid after app restart or on a different device. Fix: upload to `list-item-photos` bucket using `lib/photoUpload.ts` and store the resulting public HTTPS URL instead.

### `bookmarked` (bool)
- `true`: item is in "Save for Later" tab — no rank or sentiment assigned
- `false`: item is in rankings flow — may or may not have a rank yet (depends on whether 10-item threshold is met)
- Items with `bookmarked = true` are excluded from ranking calculations but displayed separately in the list detail screen

## Recommended Indexes

```sql
-- Most critical: home screen loads recent items per user (via list ownership)
CREATE INDEX IF NOT EXISTS idx_list_items_list_id ON list_items(list_id);

-- Home screen and list detail: ordering by created_at
CREATE INDEX IF NOT EXISTS idx_list_items_created_at ON list_items(created_at DESC);

-- Ranking query: filter by list_id + non-null rank, order by rank
CREATE INDEX IF NOT EXISTS idx_list_items_list_id_rank ON list_items(list_id, rank DESC NULLS LAST);

-- Duplicate check on insert
CREATE INDEX IF NOT EXISTS idx_list_items_list_id_external_id ON list_items(list_id, external_id);

-- Lists per user
CREATE INDEX IF NOT EXISTS idx_lists_user_id ON lists(user_id);

-- Lists by category (search sheet filter)
CREATE INDEX IF NOT EXISTS idx_lists_category ON lists(category);

-- Profiles lookup (though this is a 1:1 PK lookup, no extra index needed)
```

## Recommended RLS Policies

### `profiles`
- **SELECT**: Allow authenticated users to read any profile (public profiles)
- **INSERT**: Allow authenticated users to insert their own profile where `id = auth.uid()`
- **UPDATE**: Allow users to update only their own profile where `id = auth.uid()`

### `lists`
- **SELECT**: Allow authenticated users to read only their own lists where `user_id = auth.uid()`
- **INSERT**: Allow authenticated users to insert lists where `user_id = auth.uid()`
- **UPDATE**: Allow users to update only their own lists where `user_id = auth.uid()`
- **DELETE**: Allow users to delete only their own lists where `user_id = auth.uid()`

### `list_items`
- **SELECT**: Allow authenticated users to select `list_items` where the parent `list_id` references a list they own (join through `lists`)
  ```sql
  EXISTS (SELECT 1 FROM lists WHERE lists.id = list_items.list_id AND lists.user_id = auth.uid())
  ```
- **INSERT**: Same ownership check via parent list
- **UPDATE**: Same ownership check via parent list
- **DELETE**: Same ownership check via parent list

### Storage `avatars` bucket
- **SELECT/DOWNLOAD**: Public (allow unauthenticated access so avatar URLs work in `<Image>`)
- **INSERT/UPLOAD**: Authenticated users only, path must start with `{uid}/`

### Storage `list-item-photos` bucket
- **SELECT/DOWNLOAD**: Public
- **INSERT/UPLOAD**: Authenticated users only, path must start with `{uid}/`

## GAPS / SUSPICIOUS

1. **`lists` query missing `user_id` filter**: All `.from('lists').select(...)` queries in the search screens and profile screen do NOT filter by `user_id`. This means if RLS is not enabled, users see all lists from all users. This is critical — RLS or an explicit `.eq('user_id', user.id)` filter must be added.

2. **`list_items` has no `user_id` column**: Ownership is always inferred through the parent `lists.user_id`. This makes direct queries like "all items by user" require a join, which the profile screen avoids by fetching items globally (no user filter at all on the `select('rank, sentiment, list_id')` call). Once RLS is enabled on `lists`, this will be safe; but without RLS it exposes all users' items.

3. **`photo_urls` stores `file://` URIs**: The insert/update calls in all three search screens and the list detail edit sheet pass raw local URI strings into `photo_urls`. These are invalid after app restart. `lib/photoUpload.ts` was created to fix this — callers should upload before saving.

4. **`rank` can exceed 1–10 bounds**: `handleComparisonChoice` assigns `rankedPool[0].rank + 0.5` when ranked first, meaning items can accumulate ranks above 10 over repeated additions. Similarly they can go below 1. There is no clamping. Consider capping at 10 / 1 or normalizing after insertion.

5. **`sentimentRange` gap between `didnt_care` (max 6.99) and `liked` (min 7.0)**: Items with a rank of exactly 7.0 fall inside the `liked` range (≥7), while the `didnt_care` max is 6.99. This creates a narrow gap: a `didnt_care` item ranked at 6.99 will not appear in a `liked` comparison pool. Theoretically correct by design, but may produce surprising results if floating-point drift pushes a `liked` item below 7.0.

6. **Initial batch ranking ignores order**: When the 10-item threshold is met, items are assigned ranks by their position in `allUnranked` (insertion order). Items are not sorted by sentiment before assignment, so a `liked` item might receive a lower rank than a `didnt_like` item if it was inserted later.

7. **`handleSaveBookmark` in `movies.tsx` uses `setSelectedList` before calling the async function**: In `movies.tsx` (lines ~463–465), when the user picks a list for bookmarking, `setSelectedList(list)` is called but `handleSaveBookmark()` is called with no argument — it reads `selectedList` from state, which may not have updated yet (React state is async). In `games.tsx` and `music.tsx` this is correctly fixed by passing `list` as an argument to `handleSaveBookmark(list)`. The `movies.tsx` version is a race condition bug.

8. **No `user_id` on `list_items`**: There is no direct user reference on `list_items`, which means the profile screen fetches ALL list_items without any user filter (just `supabase.from('list_items').select('rank, sentiment, list_id')`). This will return data from all users without RLS.

9. **`lists` delete does not cascade to `list_items`**: The code calls `supabase.from('lists').delete().eq('id', id)` — if the database does not have `ON DELETE CASCADE` on `list_items.list_id`, list items will be orphaned. Ensure the FK is defined with cascade delete in the Supabase dashboard.
