# Score milestones and list deletion

The shared ScoreProgress notice shows 0–10 progress, remaining favorites, and a completion check at 10. Guests can order and save smaller lists; score previews appear at 10 using the existing guest-import order formula. Moving, comparing, adding and removing favorites updates the preview. Save confirmation and the replayable introduction explain the threshold.

Saved lists exclude bookmarked items from the threshold. Numeric list scores, their average, the edit sheet score and item-detail scores stay hidden below 10 eligible items. Existing stored scores are preserved: this change controls visibility, and does not replace the existing sentiment-based generation/comparison algorithm. Lists at 10 with no stored scores show readiness guidance instead of claiming scores were generated. No new Supabase migration is required.

Web list deletion uses the browser confirmation dialog because React Native Alert has no web implementation. Native continues using Alert. Both the detail screen and My Lists actions invoke the same owner-bound helper, authenticate, delete with an owner filter and verify the returned row. Cancellation sends no delete request; errors and zero-row responses retain the list and show a retry message. Success removes the list from the index, clears a matching active list, and returns from detail to My Lists. Web exposes a visible keyboard-accessible deletion action without requiring a swipe.

Verification: TypeScript and web export; score boundary unit test; local mocked-auth desktop/mobile browser checks for 0, 9 and 10 items, removal below 10, signed score states, deletion confirmation/cancel, server errors, zero-row response and successful removal; list-index cancel/removal. No real account/list was deleted. Native dialogs/device behavior and production cascade/RLS deletion were not tested. Guest captures passed axe WCAG A/AA; existing third-party bottom-sheet slider ARIA omissions were observed on the saved-list page, outside this change.
