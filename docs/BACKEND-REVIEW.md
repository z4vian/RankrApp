# Backend review — repository evidence, 2026-09-29

Scope: Supabase client access, historical schema/policy SQL, Edge Functions, storage/photo access, feeds and queries, social/moderation/engagement, account lifecycle, external providers, drafts and diagnostics. This is a source review and isolated test exercise, not an attestation of the live deployment. No production credentials, policies, data, function versions or observability were inspected.

## Implemented changes

- Private photo bucket migration, owner write/delete guards and owner-or-public-attachment reads with block checks. Restrictive policies survive legacy broad permissive policies. Durable references replace newly saved bearer/public URLs. Compatible legacy references are re-signed; photo UI renews short-lived URLs and clears on auth/background changes.
- Additive encrypted content table and service-only API: AES-256-GCM with record/owner/type binding, server-held versioned keys, caller identity verified by Auth, bounded bodies and payloads, persistent per-owner quota, metadata pagination, atomic compare-and-swap writes and revision-checked deletes. The existing app's content is NOT migrated.
- Push dispatch now rejects missing/misconfigured dedicated server credentials and client JWT-only requests. Bounds recipient/payload sizes, times out Expo calls, reports acceptance separately from delivery, and prunes immediate DeviceNotRegistered tickets. Delayed receipt polling is still absent.
- Account deletion invokes the server first, eliminating destructive client cleanup before discovering a missing function. Server cleanup uses the Storage API before deleting auth; partial failures retain the identity for retry. This is not a cross-service transaction.
- Canonical deployable sources live in `supabase/functions`; old docs templates cannot silently overwrite current handlers.
